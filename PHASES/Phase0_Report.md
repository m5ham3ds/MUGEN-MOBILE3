# Phase 0 — Research & Verification Report

## 1. الهدف
استكشاف وتحديد كيفية دمج محرك الألعاب **IKEMEN GO** (محرك متوافق مع M.U.G.E.N ومفتوح المصدر مكتوب بلغة Go) مع منصة **Android** لبناء تطبيق **MUGEN Mobile**.

## 2. نتائج البحث والمصادر
- **IKEMEN GO المستودع الرسمي:** `ikemen-engine/Ikemen-GO`
- **وثائق البناء:** يشير ملف `BUILDING.md` في المستودع الرسمي إلى أن بناء Android يتم بشكل أساسي عبر **Docker** لتوليد ملفات APK، حيث تقوم الحاوية بتجهيز بيئة Go و NDK المطلوبة للترجمة التقاطعية (Cross-compilation).
- **مستودع Android المخصص:** تم العثور على مستودع `JeusZilla/ikemen-droid` (ضمن مجتمع IKEMEN). هذا المستودع يمثل واجهة Android (Android-specific code) لتشغيل المحرك، حيث يعتمد على **Android Studio** و **Android NDK (r27d)**.
- يتطلب المحرك وضع المكتبات المترجمة (`libikemen.so`) في المسار `src/main/jniLibs/arm64-v8a/` وملفات المحرك الأساسية في مجلد `assets`.

## 3. طريقة التكامل (Integration Strategy)
بناءً على البحث، محرك IKEMEN GO لا يُدار كـ Library بسيطة داخل Gradle بل يتطلب بيئة Go مبنية عبر `gomobile` أو `CGo` لتوليد مكتبة Native (`.so`).
- **المعمارية للاندماج:** 
  1. **الواجهة الأمامية (Front-end):** تُبنى بالكامل باستخدام Kotlin و Jetpack Compose (وهو ما سنبنيه في هذا المشروع كمرحلة أساسية). هذه الواجهة تدير مكتبة الألعاب، الشخصيات، الإعدادات، والـ Touch Controls.
  2. **الجسر (Native Bridge):** تطبيق MUGEN Mobile سيمتلك طبقة JNI/JNA لاستدعاء أو تمرير الإعدادات إلى مكتبة IKEMEN المترجمة مسبقاً.
  3. **وقت التشغيل (Runtime):** عند ضغط المستخدم على "Play"، تقوم الواجهة الأمامية بتجهيز مسار SAF، نسخ الإعدادات، ثم استدعاء المحرك إما كـ `Activity` منفصل (مبني على SDL2) أو كـ `NativeActivity`.

## 4. الفجوات والمخاطر (Gaps & Risks)
- **غياب التجميع المباشر لمحرك Go في بيئتنا الحالية:** بيئة التطوير الحالية (التي أعمل بها هنا) مصممة لبناء تطبيقات Android (Kotlin/Gradle) ولا تدعم تشغيل `gomobile` أو `Docker` داخلياً لتجميع محرك IKEMEN GO من الصفر.
- **الحل المقترح:** سنقوم ببناء التطبيق (MUGEN Mobile) كاملاً كهيكل ومكتبة ألعاب قوية وواجهات، وسنصمم واجهة برمجية `IkemenBridge.kt` لتكون جاهزة لربطها بملفات `.so` الخاصة بـ `ikemen-droid`. (سنعتبر ملفات الـ SO متوفرة خارجياً ويجب على المستخدم وضعها عند البناء النهائي عبر Termux).
- **SAF & File Access:** التعامل مع ملفات MUGEN التقليدية (التي تقرأ من مسار مباشر) قد يواجه مشاكل مع نظام Android Scoped Storage. لذلك سنحتاج لنسخ/استخراج الملفات إلى مسار `Context.getExternalFilesDir()` أو تمرير File Descriptors إذا كان المحرك يدعم ذلك.

## 5. الخاتمة لـ Phase 0
تم التحقق من إمكانية تنفيذ التطبيق بالاعتماد على معمارية فصل الواجهة الأمامية للاندرويد (Kotlin/Compose) عن النواة (Go/C++). سيتم بدء بناء هيكل التطبيق (Phase 1) الآن بناءً على هذه النتائج.
